TicketMap auf deinem Windows-PC einrichten

Portable Windows-x64-Version · herunterladen, entpacken, starten.
Die Bilder zeigen ausschließlich fiktive Beispiele und keine echten Zugangsdaten.

1. Download2. Starten3. Projekt4. Anmeldung5. Arbeiten6. Updates

1Das richtige Paket herunterladen

Du brauchst Windows 64-Bit, einen Browser, Internetzugang und Zugriff auf dein GitLab-Projekt. Node.js und GitLab CLI sind bereits enthalten. npm brauchst du für das Paket nicht.

  1. Öffne die GitHub-Releases von TicketMap.
  2. Öffne die gewünschte Version. Lade unter Assets die Datei TicketMap-<version>-windows-x64.zip herunter.

Wähle nicht „Source code (zip)“: Das ist der Quellcode, nicht das startfertige Windows-Paket.

2Entpacken und starten

  1. Öffne den Download-Ordner. Klicke mit der rechten Maustaste auf die ZIP-Datei und wähle Alle extrahieren.
  2. Entpacke alle Dateien in einen Ordner, in dem du Dateien speichern darfst.
  3. Öffne den entpackten Ordner TicketMap und doppelklicke TicketMap.cmd.

Ein Konsolenfenster für die Einrichtung öffnet sich. Starte die Datei aus dem entpackten Ordner, nicht direkt aus der ZIP-Vorschau. Behalte die Unterordner app, runtime und licenses zusammen mit den Startdateien.

3GitLab-Server und Projekt eintragen

Öffne dein Projekt in GitLab. Die Projektadresse zeigt dir beide benötigten Werte. Die Abbildung verwendet ausschließlich Beispieldaten.

  1. Bei GitLab-Server gib nur die HTTPS-Serveradresse ein, z. B. https://gitlab.example.com. Bestätige mit Enter. Wenn dein Projekt auf GitLab.com liegt, kannst du den vorgeschlagenen Server mit Enter übernehmen.
  2. Bei Projekt (Gruppe/Projekt) gib den Pfad ein, z. B. example/team-project, und drücke Enter. Untergruppen gehören dazu: example/subgroup/team-project.

Nicht die komplette Browseradresse als Projektpfad einfügen. Zusätze wie /-/issues, eine Ticketnummer oder .git gehören nicht in diese Eingabe.

4Anmelden – falls TicketMap nach einem Token fragt

Eine passende vorhandene GitLab-CLI-Anmeldung wird automatisch verwendet. Dann erscheint keine Token-Abfrage.

  1. Melde dich im Browser an deinem GitLab-Server an. Öffne dein Profilbild → Edit profile → Access → Personal access tokens. Die Bezeichnungen können je nach GitLab-Version abweichen.
  2. Wähle bei Generate token gegebenenfalls Legacy token. Vergib einen Namen, z. B. TicketMap, lege ein Ablaufdatum fest und aktiviere api.
  3. Erzeuge den Token und kopiere ihn sofort. GitLab zeigt den Wert nur einmal an.
  4. Wechsle zum TicketMap-Startfenster, füge den Token an der Abfrage ein und drücke Enter.

Die Eingabe ist verdeckt. Je nach Konsole siehst du Sternchen oder keine Zeichen. Das ist normal. Eine leere Eingabe bricht die Einrichtung ab.

Die api-Berechtigung ist weitreichend. Der Token ist nicht dein GitLab-Kontopasswort. Verwende deinen eigenen Token und gib ihn nicht in Chats, URLs oder Konfigurationsdateien weiter. Dein Konto benötigt zusätzlich Zugriff auf das Projekt. Offizielle GitLab-Anleitung.

5Im Browser arbeiten und später erneut starten

Nach erfolgreicher Einrichtung öffnet sich dein Standardbrowser mit http://127.0.0.1:4310. Die Tickets werden aus dem konfigurierten Projekt geladen. Falls sich kein Browser öffnet, rufe diese Adresse selbst auf.

  • Ergebnis links anklicken: Das Ticket wird auf der Map sichtbar und rechts geöffnet.
  • Später starten: Erneut TicketMap.cmd doppelklicken. Die gespeicherten Einstellungen werden verwendet.
  • Beenden: Erst Ticketänderungen speichern oder verwerfen, dann StopTicketMap.cmd starten. Nur den Browser zu schließen beendet den Server nicht.
  • Server, Projekt oder Anmeldung ändern: ConfigureTicketMap.cmd starten. Vorher ungespeicherte Änderungen sichern.

Teile den Ordner data nicht mit anderen. Dort liegen deine Einstellungen und gegebenenfalls verschlüsselte Zugangsdaten. Auf einem anderen Rechner oder Windows-Konto musst du die Anmeldung neu einrichten.

6Manuell aktualisieren und Probleme lösen

Neue Anwendungsversionen werden nur gemeldet und verlinkt. TicketMap lädt und installiert sie nicht automatisch. Die Aktualisierung der Tickets aus GitLab läuft davon getrennt.

  1. Speichere oder verwirf offene Ticketänderungen und starte StopTicketMap.cmd.
  2. Lade das neue Windows-ZIP aus GitHub Releases herunter und entpacke es in einen neuen Ordner.
  3. Kopiere den bisherigen Ordner data in das neu entpackte Paket. Kopiere nicht die alten Ordner app oder runtime.
  4. Starte dort TicketMap.cmd. Verwende weiterhin denselben Browser, dieselbe Adresse und dasselbe GitLab-Projekt.

Die Kartenpositionen liegen im Browser. Lösche dessen Website-Daten nicht, wenn du die Anordnung behalten willst.
