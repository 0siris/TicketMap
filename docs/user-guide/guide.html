TicketMap auf deinem Windows-PC einrichten

Diese Anleitung gilt für die portable Windows-x64-Version ab 0.2.0. Sie zeigt die Einrichtung und die Token-Eingabe in einzelnen Schritten. Die Originalaufnahmen enthalten keine privaten Kontoinformationen oder echten Tokenwerte.

1Das Windows-Paket herunterladen

Du brauchst Windows 64-Bit, einen Browser, Internetzugang und Zugriff auf dein GitLab-Projekt. Node.js und GitLab CLI sind enthalten. npm musst du nicht installieren.

  1. Öffne TicketMap unter GitHub Releases.
  2. Lade unter Assets die Datei TicketMap-<version>-windows-x64.zip herunter.

Wähle nicht Source code (zip). Das ist der Quellcode, nicht das startfertige Paket.

2Alle Dateien entpacken und starten

  1. Öffne deinen Download-Ordner.
  2. Klicke die ZIP-Datei mit der rechten Maustaste an und wähle Alle extrahieren.
  3. Entpacke das ganze ZIP in einen beschreibbaren Ordner.
  4. Öffne den entpackten Ordner TicketMap. Doppelklicke TicketMap.cmd.

Falls Windows die Dateiendungen ausblendet, suche TicketMap vom Typ Windows-Befehlsdatei. Die Dateien ConfigureTicketMap.cmd und StopTicketMap.cmd sind für andere Aufgaben.

Starte nicht aus der ZIP-Vorschau. Behalte app, runtime, licenses und die Startdateien zusammen im entpackten Ordner.

3GitLab-Server und Projekt eingeben

  1. Öffne dein Projekt im GitLab-Browser. Beispiel: https://gitlab.example.com/example/team-project.
  2. Gib bei GitLab-Server nur den Server ein, im Beispiel https://gitlab.example.com. Drücke Enter. Bei GitLab.com kannst du den Vorschlag mit Enter übernehmen.
  3. Gib bei Projekt (Gruppe/Projekt) nur den Projektpfad ein, im Beispiel example/team-project. Drücke Enter.

Untergruppen gehören zum Pfad: example/subgroup/team-project. Zusätze wie /-/issues, eine Ticketnummer oder .git gehören nicht hinein.

Wenn eine passende GitLab-CLI-Anmeldung vorhanden ist, öffnet sich TicketMap ohne Token-Abfrage. Gehe dann zu Schritt 10. Die folgenden Schritte brauchst du, wenn das Startfenster nach einem Token fragt.

4Die persönliche Token-Seite öffnen

  1. Lass das TicketMap-Startfenster geöffnet und wechsle zum Browser.
  2. Melde dich auf demselben GitLab-Server an, den du in TicketMap eingetragen hast.
  3. Öffne dein Profilbild → Profil bearbeiten / Edit profile → Zugriff / Access → Persönliche Zugriffstokens / Personal access tokens.

Alternativ hängst du an deine GitLab-Serveradresse /-/user_settings/personal_access_tokens an. Beispiel: https://gitlab.example.com/-/user_settings/personal_access_tokens.

Erzeuge den Token auf deiner eigenen Instanz. Ein Token von GitLab.com meldet dich nicht automatisch an einem anderen GitLab-Server an.

5Einen neuen persönlichen Token auswählen

  1. Klicke Token erstellen, in einer englischen Oberfläche zum Beispiel Generate token.
  2. Wenn du einen Typ auswählen sollst, wähle Legacy-Token. Danach öffnet sich das Formular Legacy-Token generieren.

Bei älteren GitLab-Versionen gelangst du möglicherweise direkt in das Formular oder verwendest Add new token. Entscheidend ist ein persönlicher Zugriffstoken mit der Berechtigung api.

Menünamen können je nach Sprache und GitLab-Version abweichen. Die Bilder zeigen aufgenommene Oberflächen, keine nachgebauten Formulare.

6Tokenname und Ablaufdatum eintragen

  1. Gib im Feld Token-Name zum Beispiel TicketMap ein. Der Name hilft dir später, diesen Token wiederzufinden.
  2. Wähle im Feld Ablaufdatum ein Datum in der Zukunft. Beachte die Vorgaben deiner Organisation.
  3. Eine Beschreibung kannst du ergänzen, wenn GitLab dieses Feld anbietet. Sie ist für die Anmeldung nicht erforderlich.

Der Name ist noch kein Zugangsschlüssel. Kopiere später nicht den Namen „TicketMap“ oder eine Token-ID. Du benötigst den langen Tokenwert, den GitLab nach dem Erstellen einmalig anzeigt.

7api auswählen und den Token erstellen

  1. Suche die Liste der Berechtigungen / Scopes. Scrolle bei Bedarf nach unten.
  2. Aktiviere das Kontrollkästchen api. Wähle für diese Anleitung keine zusätzlichen Berechtigungen aus.
  3. Prüfe den Namen, das Ablaufdatum und das Häkchen bei api.
  4. Klicke auf die Schaltfläche, die den neuen persönlichen Token erstellt, zum Beispiel Token erstellen oder Generate token.

Die Berechtigung api ermöglicht TicketMap auch Änderungen über die GitLab-API. Dein Konto muss zusätzlich Zugriff auf das gewünschte Projekt haben. Der Token verleiht keine Projektberechtigungen, die dein Konto nicht besitzt.

Der letzte Klick erzeugt einen neuen Zugangsschlüssel in deinem Konto. Gib diesen Schlüssel nicht weiter.

8Den neuen Tokenwert einmalig kopieren

  1. Nach dem Erstellen zeigt GitLab den neuen Tokenwert an.
  2. Kopiere genau diesen Wert. Verwende die Kopierfunktion neben dem Wert, wenn deine Oberfläche sie anbietet. Falls der Wert verdeckt ist, kopiere nicht die dargestellten Sternchen, sondern benutze die Kopierschaltfläche.
  3. Lass die GitLab-Seite geöffnet, bis TicketMap deine Anmeldung bestätigt hat.

Den Wert kannst du später nicht erneut anzeigen lassen. Wenn du ihn verloren hast, erstelle einen neuen Token. Kopiere nicht den Tokennamen, die Token-ID, einen Feed-Token oder einen Token für eingehende E-Mails.

Der geheime Tokenwert wird hier absichtlich nicht abgebildet. Die Anleitung zeigt weder einen echten Zugangsschlüssel noch einen nachgebauten Ergebnisbildschirm mit einem erfundenen Token.

9Den Token in TicketMap einfügen

  1. Wechsle zurück zum TicketMap-Startfenster, das über TicketMap.cmd geöffnet wurde.
  2. Klicke in dieses Konsolenfenster. Der Cursor muss hinter dieser Abfrage stehen:
GitLab-Token (Eingabe ist verborgen; leer = abbrechen):
  1. Füge den zuvor kopierten Tokenwert mit der Einfügefunktion des Konsolenfensters ein, zum Beispiel Strg+V oder über das Kontextmenü Einfügen.
  2. Drücke Enter genau einmal.
  3. Warte, während TicketMap die Anmeldung und den Projektzugriff prüft. Wenn beides stimmt, öffnet sich der Browser automatisch.

Die Eingabe ist verdeckt. Je nach Konsole siehst du Sternchen oder keine Zeichen. Das ist normal. Eine leere Eingabe bricht die Einrichtung ab. Der Token gehört nicht in die Browseradresszeile, ein Suchfeld oder eine Konfigurationsdatei.

TicketMap speichert einen hier eingegebenen Token verschlüsselt für dein Windows-Konto und diesen Rechner. Es speichert nicht dein GitLab-Kontopasswort.

10Prüfen, ob TicketMap die Tickets lädt

  1. Der Browser öffnet http://127.0.0.1:4310. Falls kein Browser aufgeht, öffne die Adresse selbst.
  2. Prüfe, ob links deine Tickets erscheinen.
  3. Klicke einen Eintrag links an. Die Map holt die Karte ins Bild und rechts öffnet sich die Ticketansicht.

Wenn GitLab den Zugriff ablehnt, prüfe Server, Projektpfad, Token und Projektberechtigung. Kopiere keine Fehlermeldung zusammen mit einem Token in einen Chat.

11Später starten, stoppen oder die Anmeldung ändern

  • Erneut starten: Doppelklicke TicketMap.cmd. Die gespeicherten Einstellungen werden verwendet.
  • Beenden: Speichere oder verwirf offene Ticketänderungen. Starte dann StopTicketMap.cmd. Nur den Browser zu schließen beendet den Server nicht.
  • Server, Projekt oder Token ändern: Starte ConfigureTicketMap.cmd. Sichere vorher ungespeicherte Änderungen. Für einen neuen Token behältst du Server und Projekt bei und bestätigst die Frage nach einer neuen Anmeldung.

Ein abgelaufener Token funktioniert nicht mehr. Erstelle in GitLab einen neuen und gib ihn über ConfigureTicketMap.cmd ein.

Teile den Ordner data nicht. Dort liegen Einstellungen und gegebenenfalls verschlüsselte Zugangsdaten. Auf einem anderen Rechner oder Windows-Konto musst du die Anmeldung neu einrichten.

12Manuell aktualisieren und Probleme lösen

  1. Speichere oder verwirf offene Ticketänderungen und starte StopTicketMap.cmd.
  2. Lade das neue Windows-ZIP herunter und entpacke es in einen neuen Ordner.
  3. Kopiere den bisherigen Ordner data in das neue Paket. Kopiere nicht die alten Ordner app oder runtime.
  4. Starte dort TicketMap.cmd. Behalte Browser, Adresse, Port und GitLab-Projekt bei.

Die Kartenpositionen liegen im Browser. Lösche dessen Website-Daten nicht, wenn du die Anordnung behalten willst. Neue Anwendungsversionen werden nur gemeldet und verlinkt, nicht automatisch installiert.
